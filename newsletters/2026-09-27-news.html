🎯 今天的主軸
新模型「當週就上架」全部工具——模型的上架時差塌到幾天，真正的護城河搬去了「跑模型的那層工具」

先說一個你熟悉的畫面。以前買一台新引擎，要等好幾個月，車廠才把它裝進你這款車；而且你只能用車廠指定的那顆。模型過去也是這樣：一家實驗室發表新模型，你得等自己在用的工具「支援」它，等待期常常是幾週到幾個月，而且你多半只能用工具廠商幫你選好的那一顆。本週 9/25～9/26 有一批看似零碎的 changelog，其實共同把這件事翻過來了——新引擎當週就裝進了每一台車，你還能開到一半換引擎。

▍共同變化

三家對手實驗室的最新模型，在同一個 48～72 小時視窗內湧進主流工具。OpenAI Codex CLI 0.157.0（9/25）加入 GPT-6 Sol 與 Luna（含經 Amazon Bedrock 存取）。GitHub Copilot（9/25 週更）一口氣把 Claude Opus 5.5、GPT-6 Sol、GPT-6 Luna、Grok 4.7 四顆模型鋪到各付費層，還在 Slack／Teams 支援「對話中途換模型」。Vercel AI SDK 同步跟上——@ai-sdk/openai@4.0.78（9/26）替 Sol／Luna 加了 reasoningEffort: 'none'，@ai-sdk/perplexity@5.0.0（9/26）整包改接 Agent API。而 Claude Code 2.1.283（9/25）走的是另一面：新增 deniedModels 與 availableModelsMatch，讓管理者能直接封鎖或鎖定特定模型版本。

▍為什麼放在一起看

四則發布分屬 OpenAI、GitHub、Vercel、Anthropic，卻共同描出同一件事：模型正在變成「隨插即用、隨手可換」的零件。湧進（Codex／Copilot／Vercel 同週加同一批模型）＝上架時差沒了；中途換（Copilot）＝換模型不再是換工具，是換一個下拉選單；封鎖（Claude Code deniedModels）＝當任何模型都是一行設定就能進來，組織的新煩惱反而是「怎麼擋掉不該用的那些」。當「當週上架、中途可換、還要能被管控」三件事同時成立，模型就從你押注的主角，退位成一個插槽裡的耗材。

▍過去 vs. 現在

過去：新模型發表 → 你等工具支援（數週）→ 期間只能用工具幫你綁好的那顆 → 想換模型往往要換工具。你被綁在「模型 × 工具」的組合上。
現在：新模型發表 → 幾天內就出現在 Codex／Copilot／Vercel 的模型清單裡 → 同一個對話裡下拉切換 → 管理者用一行設定決定誰能用。你被綁的不再是模型，而是那個裝著所有模型的殼。差別很實際：以前「押錯模型」代價很高，現在押錯模型只是換個選項；但「押錯工具」的代價，正悄悄變高。

▍背後邏輯

為什麼工具廠商樂意讓你隨手換掉模型、甚至用對手的模型？因為他們賣的早就不是模型，而是那層殼（harness）：管理上下文、記住你的專案、審批工具呼叫、串接你的儲存庫與 CI。這週的細節都在補這層殼——Copilot 把「代理記憶（Copilot Memory）」接進自動修復流程、Codex 0.157.0 讓互動階段自動啟動背景伺服器並支援對話分叉。模型可以三家輪流換，但你的記憶、你的審批規則、你的整合，全留在殼裡。當互補品（模型）被商品化，價值就流向握住你工作流的那一層。（編輯分析）

👤 延伸解讀（編輯分析）

別把「能換模型」直接讀成「沒有鎖定」。鎖定沒消失，只是往上搬了一層：從「你用哪顆模型」變成「你活在哪個殼裡、資料與記憶留在誰家」。Vercel AI SDK 這類抽象層之所以有人用，正是想把這層鎖定也拆開——但它本身又成了另一個要押注的殼。這是今日概念要拆的「供應商鎖定 vs 可攜性」。

▍對你的工作

如果你在替團隊選 AI 工具，這週的訊號很直接：別把賭注全押在某一家模型上。模型幾天內就會在你的工具裡輪替，真正難換、真正該想清楚的是那層殼——它記了你多少東西、你的規則綁得多死、換掉它要付多少代價。實務上先做兩件事：一，確認你的工具能中途換模型、也能封鎖模型（像 Copilot 的切換、Claude Code 的 deniedModels），別讓「不能換」變成隱形鎖定；二，把「我的記憶／prompt／整合留在哪、能不能搬走」寫進選型清單，而不是只比模型跑分。

▍限制與待驗證

第一，「換模型」不是零成本——prompt 常常是為某一顆模型調過的，換一顆行為就變。這週 Claude Code 特地加了 /doctor prompt-audit，就是要幫你檢查「為舊模型寫的提示，換新模型還適不適用」，等於官方承認可攜性有隱藏成本。第二，「當週上架」目前只成立在三大實驗室 × 主流工具這個組合，小眾工具、企業內部平台仍有時差。第三，模型可換，不代表換了品質一樣——同一份工作，Sol、Opus 5.5、Grok 4.7 的表現與成本各不同，抽換之後仍要各自驗證。

▍重點一句話

模型正變成「當週上架、隨手可換」的耗材；你該問的不再是「哪顆模型最強」，而是「我被哪層殼綁住了、換得掉嗎」。

📖 今日概念｜供應商鎖定（Vendor Lock-in）與可攜性
一句定義

供應商鎖定是指：你的工作流深度綁定某一家的產品、格式或介面後，「換掉它」的成本高到你幾乎換不動；可攜性（portability）則相反——讓你能用夠低的成本，把工作、資料與流程搬到別家。

生活化比喻

像膠囊咖啡機：機器便宜賣你，但只吃自家膠囊，久了你被綁的其實是「膠囊供應」。把它對回技術——模型＝膠囊，工具（harness）＝咖啡機。本週的變化是：各家咖啡機開始「什麼牌子的膠囊都能塞」（任何模型隨手換），模型層的鎖定鬆了；但你可能因此更離不開那台咖啡機——鎖定沒消失，只是從膠囊搬到了機器本身。

工作中的例子

本週正好有可攜性的「解鎖鍵」與「隱藏鎖」同框。解鎖：Copilot 支援對話中途換模型、Claude Code 用 deniedModels／availableModelsMatch 讓你自己決定用哪些模型；Vercel AI SDK 這類抽象層更是把「換供應商」做成改一行設定。隱藏鎖：你的 prompt 常是為某顆模型調過的，換一顆行為就跑掉——所以 Claude Code 才加 /doctor prompt-audit 幫你查「舊提示配新模型」的落差。能換≠沒代價。

常見誤解

誤解一：「我能換模型，就沒被鎖定。」——鎖定往往只是上移了一層，跑去了殼、你的記憶與資料、以及調校過的 prompt。誤解二：「用開源／開放權重就一定沒鎖定。」——就算權重能拿，你的部署、監控、工具鏈仍可能綁死在某個平台。可攜性要看的是「搬家的總成本」，不是單一元件能不能替換。

與今天主軸的關係

主軸說模型變成「當週上架、隨手可換」的耗材。這正是模型層可攜性大增的一刻——但也是鎖定悄悄搬去殼的一刻。看懂供應商鎖定，你選型時問的問題就會從「哪顆模型強」升級成「哪一層我換得掉、哪一層我一旦進去就出不來」。

🏭 半導體 AI 專區｜用機器學習預測「佈局繞線壅塞」（Routing Congestion / Routability）
EDA 工具 背景知識
▍問題與流程位置

在實體設計（physical design）裡，佈局（placement）先決定每個標準單元擺哪，接著繞線（routing）把它們用金屬線連起來。麻煩在於：如果佈局讓某塊區域「太多線想擠過同一條窄巷」，就會產生繞線壅塞（congestion），引發 DRC 違規、繞不通、或時序變差——而這些通常要跑完一輪很慢的全域＋細節繞線才會發現。發現得晚，就得回頭改佈局、再繞一次，一輪動輒數小時到數天。壅塞預測要做的，就是在還沒真正繞線前，先預測「哪裡會塞、繞不繞得通」，把問題往前挪（shift-left）。

▍AI 如何介入（與過去的差異）

過去要嘛真的跑一次（試）繞線來看哪裡塞——準但慢；要嘛用機率式/解析式的粗估（如 RUDY 這類線長密度指標）——快但抓不準熱點位置。改用機器學習後，做法是把「擺好位置的晶片」當成一張圖片或一張圖（graph）：用 CNN／GAN（例如把佈局畫成影像、用條件式 GAN 預測壅塞熱圖）或用圖神經網路 GNN（如 CongestionNet 直接吃網表連接關係），在幾秒內輸出一張壅塞熱圖，讓佈局階段就能反覆試、提早避開。核心差異：從「先繞再量」變成「不繞也能預判」。

▍資料與產出

輸入：單元座標與佈局、網表連接、接腳密度、巨集（macro）擺放，有時再加上 RUDY／全域繞線的粗估特徵。輸出：分區的壅塞熱圖、可繞度分數、預測的 DRC 熱點位置。訓練資料多來自開源基準CircuitNet（含壅塞、DRV、時序、功耗等標註）。難點也在資料：正確答案（ground truth）得靠真的跑繞線器產生，很貴；模型綁製程、綁工具，換 PDK 或換一套 EDA 就常要重訓；熱點在版圖上本來就是少數，類別不平衡。

▍如何驗證

把預測熱圖對「真的繞完後」的實際壅塞比對：看相關係數、影像相似度、逐格誤差，以及熱點的精確率／召回率；最終還要看整條流程是否真的更快收斂、少繞幾輪。評測通常留一批沒見過的設計做 holdout（如 CircuitNet 的跨設計測試）。要特別提醒：這些多是學術／基準數據，不是量產的 PPA 或良率保證，落地效果仍要在自家 PDK 上驗。

▍限制與風險

一，泛化差：在一種製程／工具上訓的模型，換一家常常不準。二，假樂觀最貴——模型說「看起來繞得通」卻其實會塞，比保守誤報還糟，會把問題流到下游。三，它只預測、不修：真正能不能繞通，最後仍要真繞線器當裁判。四，要好用得餵大量標註資料，而產生標註本身就得跑昂貴的繞線。

👷 對半導體工作者的意義：對實體設計／PD 與 CAD 工程師，壅塞預測是一種「shift-left」——把賭注押在工作流的位置（提早預判），而不是某一顆 solver 或某一家工具，這跟今天主軸「押流程、別押供應商」完全同構。值得動手的下一步：檢查你現在的 P&R flow 有沒有早期可繞度預測，並把它的熱點預測拿去對「實際繞完」的結果——對得準不準，決定你敢不敢靠它省繞線輪次。
