AI 拿到了「簽字權」——同一批發布把它推上放行別人工作的位置，也同時替它上鎖
過去一年我們習慣的說法是「AI 是副駕」：它給建議，人拍板。這 48 小時，三家大廠在各自的地盤上，同一天把方向盤往前推了一格——不是讓 AI 更聰明，而是開始授權它「簽字放行」，同時又緊張地替它上鎖。
▍共同變化
三則消息看起來各走各的，其實在回答同一個新問題：當模型好到可以當「審核者／守門員」，你要授權它到哪、又要把哪一段鎖起來？
・GitHub：Copilot code review 現在會給出「核准評估」，管理員可授權它真的核准 PR，且核准能計入 repo 的必要審核數（9/1）。
・Anthropic：新一代 Fable 5.1／Mythos 5.1 是同一顆底層模型的兩個身分——Fable 5.1 是帶生產安全護欄的公開版，Mythos 5.1 是解開部分限制、只給通過審核的資安與生命科學組織的限定版（9/1）。
・OpenAI：Astra 成為第一個越過自家 Preparedness「Critical」網路能力門檻的模型（ExploitBench 滿分、能在測試中自主串起漏洞鏈），OpenAI 因此放慢、限制最強能力並全面上監控（9/1–9/2）。
▍為什麼放在一起看
因為「授權」和「上鎖」是同一枚硬幣的兩面。能力一旦強到可以替人做決定（核准一份 PR、寫一段能被信任的 code、找到一個真的 0-day），風險與責任就同步升高，於是廠商必須同時回答「我授權它簽到哪」與「我把哪一段鎖起來」。Copilot 給了核准權、但預設關閉還能限定檔案路徑；OpenAI 給了能力、但配上鏈式思考（CoT）監控與中斷；Anthropic 給了更強的模型、但按信任層級分版發放。三家的動作，本質是同一件事。
▍過去 vs. 現在
過去：AI 是助手，所有簽字、放行、分發都由人決定，模型只有一個「盡量好用」的版本。
現在：AI 開始擁有正式的核准權（計入必要審核）；模型開始按信任層級（誰能拿到解鎖版）與危險層級（哪些能力要鎖）被切開發放。這是從「一個模型、人人可用」走向「同一模型、分權分級」。
▍背後邏輯
能力提升 → 責任與風險同步提升 → 用治理、權限與監控把「可授權範圍」框出來。注意細節都是「給權限、但設界」：Copilot 的核准會在有新 commit 時自動撤銷（跟人類審核一樣），且可按檔案路徑限定；Astra 的每個代理應用都掛上通用監控，盯 CoT 並在高風險行為時中斷；Mythos 走 vetted-access（先審資格再給）。沒有一家真的把鑰匙整串交出去。
👤 延伸解讀（編輯分析）
值得注意的是，這波「授權」幾乎都附帶一個煞車：Copilot 官方明說「核准評估本身不計入 merge 要求」、預設關閉。換句話說，業界嘴上讓 AI 簽字，手上其實還牢牢按著閘門。真正被改變的，是「監督點」的位置——從盯每一步，變成盯例外與紅線。這是編輯分析，非官方定論。
▍對你的工作
對軟體團隊：AI 能核准 PR，意味 code review 流程要重畫「誰能簽、簽什麼、簽了誰負責」，並想清楚哪些路徑可以外包給 AI、哪些永遠留給人。對半導體工程師：這其實是你們最熟的老題目——tapeout 與 sign-off 文化本來就在處理「誰能 sign off、要不要雙簽、gate 放哪」。AI 只是把同一套「授權＋設界」的思路，搬進了軟體與晶片的每一道關卡。
▍限制與待驗證
・Copilot 的核准預設關閉、且「評估本身不計入 merge」——真正的授權程度取決於各團隊怎麼設定。
・Astra 越過「Critical」是 OpenAI 依自家框架的自評，外部無法獨立複驗其門檻與測試。
・Mythos 5.1 的分級「審核標準」目前不透明，誰能拿到解鎖版由廠商決定。
▍重點一句話
AI 越能替你簽字，你越要先想清楚——它「不能」簽什麼。

📖 今日概念｜人在環內 vs. 人在環外（Human-in-the-loop vs. Human-on-the-loop）
一句定義：「人在環內」＝每個決策都要人親自拍板才會執行；「人在環外」＝AI 自行執行，人只在異常或碰到紅線時才介入監督。
生活化比喻：駕訓班教練踩著副煞車、盯著你的每個動作，這是「環內」；換成副駕領航，你開車、他只盯儀表，必要時才出聲，這是「環外」。說回技術——今天 GitHub 讓 Copilot 能核准 PR，就是把 code review 從「環內」往「環外」挪了一格。
工作中的例子：每一支 PR 都要人逐行看完才能合併＝環內；讓 Copilot 自動核准低風險路徑、人只覆核它擋下的例外＝環外。
常見誤解：以為「環外」＝無人監督。其實不是——監督沒有消失，只是監督點從「每一步」移到「例外與紅線」。人還在，只是站的位置變了。
與今天主軸的關係：今天三家大廠做的，本質都是在替自家 AI 畫「環內／環外」的界線——哪些能自動放行、哪些一定要人回到環內。
🏭 半導體 AI 專區｜AI 寫的 RTL，誰來簽字放行？
EDA 工具 今日新聞＋背景知識
▍問題與流程位置
AI 現在能從規格甚至自然語言「生成 RTL」（晶片的暫存器傳輸級硬體描述）。但生成的 code 對不對？在 tapeout 前，RTL 一路合成到閘級（gate），每一步都必須數學證明前後功能等價——這就是等價性檢查（LEC）。位置就在 RTL 撰寫 → 合成 → sign-off 這條主幹上。這正是主軸「AI 能不能簽字放行」在晶片流程裡的版本。
▍AI 如何介入
AI 從兩層切進來：(1) 幫你寫——Synopsys 在 DAC 2026 展示自主驗證代理，宣稱把「拿到可驗證 RTL 的時間」加速最高約 50 倍；學界的 FormalRTL 則用軟體參考模型當「可執行的規格」，錨定 LLM 的合成。(2) 幫你把關——Cadence 的 Conformal AI Studio 用 AI 做等價性檢查、低功耗與工程變更（ECO）；Synopsys Formality 以 ML 加速等價性驗證約 5 倍。過去：工程師手寫 RTL、LEC 全跑、差異靠人 debug；現在：AI 寫、AI 幫跑 LEC，人只看被擋下來的差異——效率與可重複性提升，但簽字權仍握在人手上。
▍資料與產出
輸入：規格／C 或 C++ 參考模型／既有 RTL；產出：RTL 加上「等價性證明」或一組反例波形，指出哪裡不等價。
▍如何驗證
LEC 以形式化方法數學證明「黃金版（golden）與修改版功能等價」；跑不過就吐出反例，交人判讀。這台守門員本身不猜、不學風格，只認「等或不等」——它就是主軸裡那個「守門員」在晶片流程的實體版。
▍限制與風險
關鍵盲點：LEC 只證「兩個版本等價」，不證「規格本身對不對」。若 AI 照著一份錯的規格生成 RTL，LEC 一樣會放行。此外 50 倍／5 倍都是廠商宣稱值，須按自家設計規模驗證，別當普適數字（此段含編輯分析）。
👷 對半導體工作者的意義：驗證與 sign-off 工程師最該關注——AI 能把「跑 LEC、追差異」自動化，但「決定什麼算 golden、什麼能簽」仍是人的紅線。下一步可在非關鍵 block 試點 AI 輔助 LEC／ECO，先建立信任，再談把關卡外移。
