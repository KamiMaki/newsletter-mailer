▍過去 vs. 現在

過去：想讓 agent 快，就等下一代更快的模型；每一輪呼叫都把整段歷史重新打包送出。現在：像寄快遞——以前每次都把整間房子的家具重新打包寄一次，現在只寄「新增的那箱」，其餘留在對方倉庫。說回技術：歷史留在伺服器（或靠前綴快取重用），網路與 prefill 運算都省下來。

▍背後邏輯

長對話的成本主要來自「每輪重讀全部歷史」。要省，有三條路：把狀態放對地方（伺服器端 thread）、讓前綴穩定（Qoder 的快取重用）、該壓縮時壓縮（idle compaction）。代價是狀態變成「有保存期限的東西」——thread 閒置 5 分鐘就失效、最長保留不超過 1 小時。

📖 今日概念｜前綴快取（Prompt／Prefix Caching）與 KV Cache

定義：模型讀過一段文字後，會把中間計算結果（KV Cache）存下來；下次請求若開頭一模一樣，就能直接重用、不必重算。

生活化比喻：像看了一半的書夾著書籤——翻回來直接從書籤讀；但只要你偷偷改了前面一頁，書籤就作廢，得從頭重讀。說回技術：開頭一變，後面整段快取全失效。

工作中的例子：EDA agent 每步都送「系統指令＋工具清單＋歷史」。把穩定的內容（規範、工具定義）放最前面、變動的（本輪 log）放最後，快取命中率才高；若在開頭塞入時間戳，每次都會全部重算。

常見誤解：「有快取就不用管上下文長度」——快取通常有期限（如 Message threads 為 5 分鐘），過期後仍要整段重算；且快取只省計算，不改變模型『看見』的內容。

與今天主軸的關係：Qoder 的「穩定前綴」與 Claude Code 的「快取過期才壓縮」，都是圍著這個機制設計。（概念為背景知識，非今日新聞。）
