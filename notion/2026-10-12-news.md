## 🎯 今天的主軸｜「再加一個 agent 就會更強」這週被數字打臉——真正的槓桿不是人多，是把一個 agent 餵飽

過去一年，「multi-agent（多代理）」幾乎是進步的同義詞：遇到難題，就再開一個 agent、組個團隊、讓它們互相檢查。這週有三件事剛好從不同角度，把這個直覺推到該驗證的時候了。

**共同變化：** 評測機構 Vals AI（10/11）把 GPT-6 Sol 與 Claude Opus 5.5 放到 Vibe Code Bench 上，分別以「單一 agent」和「組隊」跑，再比中等與最高推理強度。結果：團隊版花的錢是單一版的 1.8～5.1 倍，但四組「團隊 vs 單一」比較裡，只有一組（Sol 中等強度）拿到統計上顯著的進步（+7.3 分）；在最高強度上再加團隊只多了 1.4 分，且不顯著。更戲劇化的是 Opus 的最高強度團隊版，部署後花了中位數 68 分鐘在「互相測試」，單一版只花 10 分鐘。同一週，微軟 Work IQ 與法務科技 Ironclad 給出的答案不是「再加 agent」，而是「給 agent 更好的資料接地」。

**為什麼放在一起看：** 因為它們指向同一個轉折：agent 的效果瓶頸，正從「智力不夠、所以多找幾個腦袋」轉成「情境不夠、所以要接到對的資料」。Vals AI 證明人海不是免費午餐；微軟 Work IQ 把 Copilot 和 agent 接上即時業務資料，主打「語意模型」——情境寫一次、所有 agent 共用；Ironclad 的合約知識圖譜，把 agent 判斷綁回公司真正的成交歷史。一邊喊停「加人」，一邊加碼「接地」，其實是同一句話的正反面。

**過去 vs. 現在：** 過去的敘事是任務太難就拆子任務、一隻 agent 一個角色，理論上更穩更強。現在被量化後的現實是：多數任務裡，協調本身是要付費的——agent 之間要溝通、重複讀上下文、互相覆核，token 翻倍、時間拉長，品質卻常在誤差範圍內。

**背後邏輯：** 多代理常不划算，是因為它同時放大成本與出錯面：每隻 agent 都要讀一次背景、彼此傳話會失真、沒有單一負責人時容易各做各的。「接地（grounding）」則用一份可信、結構化、可追溯的資料，把單一 agent 的輸出釘在事實上，解決 agent 最常見的失敗（幻覺、脫離公司現況），邊際成本遠低於再養一隻 agent。這也是為什麼 Nous Research 這週能募到 9,000 萬美元把開源 Hermes 推進企業：稀缺的不是模型，是「把 agent 接進你家資料與流程」的那層工程。

**對你的工作：** 若你正在評估導入 agent，先問「這任務的瓶頸是智力還是資訊？」。若是資訊，投報最高的動作是把資料接好、權限與來源理清，而不是急著架多 agent 框架。多代理不是不能用，而是要有證據再上。

**限制與待驗證：** 這不是說多代理已死。Vals AI 只測了一個 coding benchmark、兩個模型；其他研究也各有例外。合理讀法是：「多就是好」的預設該被收回，改成「預設單一、用數據證明再組隊」。Work IQ、Ironclad 的接地效果多為官方與早期說法，企業成效仍待第三方驗證（編輯分析）。

> 👤 微軟介紹 Work IQ 的一句話適合當註腳：「agent 的好壞，只到我們給它的情境那麼好」。這正是把焦點從「幾隻 agent」拉回「餵什麼給 agent」。（延伸解讀，非官方新聞主體）

**記住這句：** 擴充 agent 的第一步，不是「再開一隻」，而是「把現有這隻接到對的資料」。

## 📖 今日概念｜協調稅（Coordination Tax）

**定義：** 把一件工作交給「多個 agent 一起做」時，為了溝通、傳遞上下文、互相覆核而額外付出的成本（token、時間、出錯機會），就是協調稅。它不產生答案，只是讓多方能一起工作。

**生活化比喻：** 像一個人就能寫完的報告，硬拆給五個人分工：光是開會對齊、互相轉述、合併版本，就把省下的時間又吃回去——「三個和尚沒水喝」的工程版。回到技術上，agent 之間每次傳話都要重新讀一遍背景，token 就這樣翻倍燒掉。

**工作中的例子：** Vals AI 本週的數據就是協調稅的帳單：團隊版比單一版貴 1.8～5.1 倍，Opus 最高強度團隊光「互相測試」就花掉中位數 68 分鐘（單一版 10 分鐘）——多出來的全是協調，不是答案。

**常見誤解：** 誤以為「agent 越多越聰明、越穩」。實際上協調稅會隨 agent 數成長，常常抵銷甚至超過品質增益；只有當任務能被乾淨切分、且子任務彼此獨立時，組隊才划算。

**與今天主軸的關係：** 主軸說「接地勝過加人」，背後的經濟學正是協調稅：把預算從「養更多 agent、付協調稅」挪到「把單一 agent 接到對的資料」，通常買到更高的投報率。

## 🏭 半導體 AI 專區｜用深度學習讀「晶圓缺陷圖樣」追根因

**分類：** IC 製造
**內容屬性：** 背景知識

**問題與流程位置：** 晶圓測試（wafer sort）後，整片晶圓上哪些 die 好、壞，會畫成一張「晶圓圖（wafer map）」。好壞 die 的空間分布常不是隨機，而是呈現特定圖樣：中心一團、邊緣一圈、一條刮痕、甜甜圈狀……。老師傅看圖樣就能猜製程哪裡出事，但一座廠一天上千張圖，靠人眼歸類既慢又難一致。這一步卡在良率分析與失效追根因之間。

**AI 如何介入：** 把晶圓圖當成一張影像，用 CNN（卷積神經網路）自動辨識它屬於哪一種空間圖樣。相較過去「人工規則＋老師傅經驗」，CNN 能一次穩定分類海量晶圓圖、把一致性與速度同時拉上來，讓工程師不必從上千張圖大海撈針，而是直接看到「今天哪種圖樣暴增」。這呼應今天主軸：價值來自把分析接地到豐富的空間資料，而非堆更多人力或 agent。

**資料與產出：** 公開研究常用 WM-811K 資料集（約 81 萬張來自真實產線的晶圓圖），標註為 Center、Donut、Edge-Loc、Edge-Ring、Loc、Random、Scratch、Near-Full 等類別。模型產出是「圖樣類別＋信心度」，可往下對應可能根因——研究指出中心圖樣常與薄膜沉積相關、環狀與蝕刻相關、刮痕與機台搬運有關（背景知識，實際根因仍須產線比對）。

**如何驗證：** 用保留測試集看分類準確率（多篇研究在 WM-811K 上報到 9 成以上，如 MFFP-Net 約 96.7%）；更重要的是把模型抓出的「暴增圖樣」回到產線，對照機台／製程日誌驗證根因，真的縮短偵測問題的時間。

**限制與風險：** 最大的坑是類別極度不平衡——Random 與無圖樣占多數，稀有圖樣樣本太少，模型易學偏；研究常用資料增強（如 DCGAN 生成少數類）來補。另外「分類正確」不等於「根因正確」，CNN 給的是圖樣標籤而非物理解釋；把它當線索而非結論，才不會誤導 8D 分析。

> 👷 對半導體工作者的意義：對良率與整合（YE／PI）工程師，這是把「翻圖找線索」自動化的高投報點——先把歷史晶圓圖與機台日誌接好，讓一套模型幫你盯「哪種圖樣今天異常」，比急著導入多 agent 更實在。

## 🪞 反思時間

- 如果你手上那個「多 agent 協作」的規劃，其實瓶頸是資料不夠而非智力不夠，你會把下一季的預算優先投在哪：再養一隻 agent，還是把資料接地做好？為什麼？
- 你的團隊有沒有「預設就該多 agent」的隱性信念？要用什麼樣的一次小實驗（像 Vals AI 那樣比成本與分數），才能驗證它在你的任務上到底值不值？
- 把「協調稅」搬到人的組織：哪些工作是你們硬拆給多人、結果協調成本吃掉效益的？那套判斷能不能反過來指導你怎麼設計 agent 分工？

**🎒 今日帶走：** 擴充 AI 能力的第一反應別再是「加一隻 agent」，先問「我把現有這隻餵飽了嗎」。
