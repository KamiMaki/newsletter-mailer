## 🎯 今天的主軸｜AI agent 變快、變省，靠的不是更強的模型，而是外層「少做重工」——不重送整段對話、不重啟程序、中斷後不重放副作用

**共同變化**
Anthropic 11/2 推出 Claude API 的 Message threads（beta）：對話存在伺服器，後續請求只送新訊息，可降低請求大小與首字延遲。同日 Alibaba Qoder 發表〈Making Fast Mode Faster〉：不動模型，改外層執行層——預編譯啟動、背景預熱、穩定請求前綴以重用快取、大輸出存硬碟，中斷後依 call ID 對帳，結果未知的呼叫不自動重放以避免重複副作用。
🔗 [Claude 平台 Release Notes](https://platform.claude.com/docs/en/release-notes/overview) ｜ 來源：platform.claude.com
🔗 [Making Fast Mode Faster](https://www.alibabacloud.com/blog/making-fast-mode-faster_603714) ｜ 來源：Alibaba Cloud 部落格

**為什麼放在一起看**
兩者拆掉的是同一種浪費：同樣的東西一再搬運、同樣的程序一再重啟。稍早（10/30）Claude Code v2.1.314 的 idle compaction 也是同類招式（背景，非 48 小時內）。

**過去 vs. 現在**
過去想讓 agent 快就等更快的模型，每輪把整段歷史重新送出；現在像快遞只寄「新增的那箱」，其餘留在對方倉庫。技術上就是歷史留在伺服器或靠前綴快取重用，省下網路與 prefill 運算。

**背後邏輯**
長對話成本來自每輪重讀全部歷史。三條路：把狀態放對地方、讓前綴穩定、該壓縮時壓縮。代價是狀態有保存期限——thread 閒置 5 分鐘失效、最長保留不超過 1 小時。

**對你的工作**
EDA／良率分析 agent 的 log 動輒數十萬 token，每步重送整份歷史，延遲與帳單線性膨脹。（編輯分析）可先量三個數字：每步送出 token、快取命中率、中斷後能否安全續跑。

> 👤 延伸解讀（編輯分析）：Qoder 的「未知結果不自動重放」值得抄；對會寫檔、提交工單的 agent，重放等於重複下單。

**限制與待驗證**
Message threads 為 beta，未公布延遲改善幅度，也未說明過期錯誤格式；Qoder 文章沒有任何延遲或加速數字，屬廠商自述。

**記住這句**
agent 的快，一半來自模型、一半來自「少搬一次、少跑一次」；省下來的東西要靠「狀態有期限」換。

## 📖 今日概念｜前綴快取（Prompt／Prefix Caching）與 KV Cache

**定義：** 模型讀過一段文字後把中間計算結果（KV Cache）存下來；下次請求若開頭一模一樣就直接重用。

**比喻：** 像看了一半的書夾著書籤，翻回來直接續讀；但只要改了前面一頁，書籤就作廢。技術上：開頭一變，後面整段快取失效。

**工作中的例子：** EDA agent 每步都送系統指令、工具清單與歷史。穩定內容放最前、變動的 log 放最後，命中率才高；開頭塞時間戳會讓每次全部重算。

**常見誤解：** 「有快取就不用管上下文長度」——快取有期限（如 Message threads 為 5 分鐘），過期仍要整段重算；且快取只省計算，不改變模型看到的內容。

**與今天主軸的關係：** Qoder 的穩定前綴與 Claude Code 的「快取過期才壓縮」都圍繞這個機制。（背景知識，非今日新聞）

## 🏭 半導體 AI 專區｜繞線擁塞預測與設計建議（MLLM）

**分類：** EDA 工具
**內容屬性：** 背景知識

**問題與流程位置**
佈局後常出現繞線擁塞：某些區域需要的線比軌道多。傳統要真的跑一次全域繞線才知道，一輪動輒數小時。

**AI 如何介入**
背景知識（2025 年論文，非今日新聞）：arXiv 2510.15872 用多模態 LLM 從版圖影像（Macro Region、RUDY 等）與文字 log 產生候選特徵，再以可解釋的偏好學習預測擁塞分數與擁塞圖，並彙整成設計建議清單。過去的影像對影像模型只告訴你哪裡紅，這裡還試著說為什麼與怎麼改。
🔗 [arXiv 2510.15872](https://arxiv.org/abs/2510.15872) ｜ 來源：arXiv

**資料與產出**
CircuitNet（超過 1 萬個 14nm FinFET 合成設計，80／10／10 切分）；產出擁塞圖、分數與建議清單。

**如何驗證**
對照 GPDL、MPGD、CircuitFormer：SSIM 0.807、NRMSE 0.045、PLCC 0.6452 領先；SRCC 0.5233 略低於 CircuitFormer 的 0.5282（論文自報）。

**限制與風險**
作者自述僅驗證於 RISC-V 設計與 CircuitNet，未涵蓋商用設計，也只做擁塞。編輯分析：相關係數約 0.65，適合做先篩再跑的快篩，不宜取代簽核。

> 👷 對半導體工作者的意義：實體設計工程師可把擁塞預測當作 placement 後的早期預警，先排序要重跑的區塊，省下盲目整區重繞的時間。

## 🪞 反思時間
- 趨勢反思：如果對話狀態放在供應商伺服器上、且只保留 5 分鐘到 1 小時，你的 agent 流程哪些步驟會因此變得脆弱？需要怎樣的『重建歷史』備案？
- 工作連結：想想你團隊最耗時的一條 EDA 或良率分析迴圈——每一步重複搬運的是什麼（log、設計檔、工具清單）？有哪些可以改成只送差異？
- 未來判斷：當 harness 的優化讓 agent 變快，但行為也隨之改變，你會用什麼基線與回歸測試，確認『更快』沒有換來『更不準』？

**🎒 今日帶走：** agent 的速度與成本，贏在「少搬運、少重跑」，但省下的每一步都要用「有期限的狀態」與回歸測試來守住。
