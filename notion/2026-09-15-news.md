## 🎯 今天的主軸｜agent 從「一個」變成「一群」之後，戰場從「誰的 agent 更聰明」轉到「誰說得清每個 agent 是誰、能碰什麼、做過什麼」

**共同變化：** 昨天我們才談過「桌上的 coding agent 成了新攻擊面」，那是從單一工具的安全切入。今天的新聞把鏡頭拉遠：當一家公司同時跑幾十、上百個 agent，問題不再是「這個 agent 會不會被騙」，而是「這一群 agent 到底是誰、拿了誰的權限、上週動了哪些系統」。Salesforce 今天開幕的 Dreamforce、Akuity 昨天推出的 Agentic Control Plane，還有 Okta／微軟這一年鋪的「非人身分」框架，講的其實是同一件事：把 agent 當成「有身分、要授權、可稽核」的正式成員來管。

**為什麼放在一起看：** 它們從三個不同的門走進同一個房間。CRM／業務側：Salesforce 把整個產品堆疊押在「agent 治理即基礎設施」，用 AI Control Plane 註冊 agent、設身分與存取政策、管生命週期、評估表現、觀察行為、追蹤成本。開發維運側：Akuity（Argo CD／Kargo 的原班人馬）9/14 推出 Agentic Control Plane，讓 agent 的每一個請求都以「當下連線的那個人」的身分通過控制平面，政策層還能擋掉「就算你本人有權、也不該讓 agent 代做」的正式環境操作。身分／資安側：Okta 的「每個 agent 都需要身分」框架與微軟 Entra Agent ID，把既有的零信任那一套延伸到非人身分上。三條線都指向：agent 的瓶頸正在從「能力」轉到「治理」。

**過去 vs. 現在：** 過去管一個 agent，靠的是塞在提示詞裡的規矩、一份 deny 清單、或工具層的開關——像用便利貼提醒新來的實習生「別碰那台伺服器」。現在改成 IT 老手熟悉的身分與存取管理（IAM）流程：註冊 → 授權（這個任務需要什麼才給什麼）→ 執行時管控 → 退役，每一步都留紀錄。差別在於，便利貼靠人自律、規模一大就失效；控制平面是把規則從「agent 內部的自覺」搬到「agent 外部、擋在它和資源之間的一道關卡」。

**背後邏輯：** 數字逼著大家往這走。微軟自己說 Copilot Studio 上已有 16 萬個組織跑著超過 40 萬個自訂 agent；Okta 引用的調查更直接——88% 的組織回報疑似或確認發生過 AI agent 相關資安事件，卻只有 22% 真的把 agent 當成「有身分的實體」在管（此為調查數據，屬編輯引用的背景）。當 agent 數量指數成長、又個個能自己呼叫工具與 API，「先看得到、再管得住、還算得出花多少錢」就從加分項變成不做不行的地基。

**對你的工作：** 對工程與 IT 主管，這是該提早問的問題：你們給 AI 工具的權限，是「這個人有的全給」還是「這個任務要的才給」？對開發者，未來接入公司系統的 agent 很可能不再是「偷偷掛上去的腳本」，而要先在控制平面登記身分、拿到 scoped 權限、行為被記錄。好處是出事能追、成本能算；代價是多一層設定與治理流程。先想清楚哪些操作「連你有權、agent 也不准代做」，會比事後補救省事得多。

**限制與待驗證：** 三個現實提醒——其一，看得到 ≠ 管得住：observability 只是治理的一隻腳，真正難的是即時攔阻與最小權限。其二，各家控制平面互不相通：Salesforce、Akuity、Okta、微軟各蓋各的，跨平台 agent 身分還沒有共通標準，今天的整合很可能是明天的鎖定。其三，這些多是產品發表與框架，實際能擋下多少誤動作、稽核軌跡在真實事故裡多好用，還要看落地數據（此段為編輯分析）。

## 📖 今日概念｜控制平面 vs. 資料平面

**一句定義：** 「資料平面（data plane）」是真正做事、搬運東西的那一層；「控制平面（control plane）」是決定「誰能做、往哪走、按什麼規則」的那一層。系統設計常刻意把兩者分開。

**生活化比喻：** 想像一座機場。跑道上起降、載客飛行的飛機是資料平面；塔台不搬一件行李，卻決定誰能起飛、走哪條航道、何時降落，那就是控制平面。塔台癱瘓，飛機還在天上，但沒人敢亂飛。

**工作中的例子：** 網路交換器裡，轉封包的晶片是資料平面，算路由表的軟體是控制平面；今天的 agent 控制平面也一樣——agent 呼叫 API、讀寫資料是「做事」，而「這個 agent 有沒有權限這樣做、要不要記一筆、超支了沒」是「管事」，被抽出來獨立成一層。

**常見誤解：** 以為「把行為都記下來（observability）」就等於「管得住」。其實紀錄屬於「看得到」，真正的控制平面還要能當下攔阻——看到違規卻攔不下來，塔台就只是行車紀錄器。

**與今天主軸的關係：** 今天所有廠商在做的，本質上就是替 agent 蓋一座塔台——把「管事」從 agent 自己的腦袋裡搬出來，變成擋在它和資源之間、看得到也管得住的一層。

## 🏭 半導體 AI 專區｜光學量測的「逆推」：用機器學習解 OCD／散射量測

**分類：** IC 製造
**內容屬性：** 背景知識

**問題與流程位置：** 先進節點與 3D 封裝要量的是 nm 級的線寬、間距、高度、側壁角。CD-SEM／AFM 準，但慢、成本高、還可能傷到樣品，難以做 inline 近全檢。業界因此大量用光學臨界尺寸（OCD）／散射量測：對週期性結構打光、量它散射／繞射出來的光譜（如 Mueller 矩陣），非破壞又快。麻煩在於——你量到的是「光譜」，要的卻是「尺寸」，中間隔著一個難解的逆問題。

**AI 如何介入：** 傳統做法是先用嚴謹的電磁模擬（RCWA）算出「各種尺寸 → 對應光譜」的龐大 library，量測時回頭比對查表，或每量一次就跑一次昂貴模擬——慢、且維度一多就爆炸。AI 的切法是：用 RCWA 產生大量合成光譜當訓練資料，訓練神經網路直接學「光譜 → 尺寸」的反向映射，量測時只要一次前向推論。和過去最大的差別，是把「每次量測都重算物理」換成「一次訓練、之後即時查詢」。有研究（3D 封裝重佈線層）報告單次量測可壓到 3 毫秒以下、吞吐量較 AFM／SEM 提升約兩個數量級（此為學術研究數據，非量產成果）。

**資料與產出：** 輸入是繞射／散射光譜、Mueller 矩陣或後焦面影像；輸出是 CD、高度、間距、側壁角等結構參數。訓練資料主要來自 RCWA 合成（再用少量實測校正），這也讓它不必仰賴海量標註的真實晶圓。

**如何驗證：** 拿 CD-SEM／AFM／TEM 當「參考真值」交叉比對、看殘差分布，並檢查模型在製程窗口邊緣的敏感度是否合理。關鍵是要輸出不確定度估計，讓量測值能被 SPC（統計製程管制）正確判讀。

**限制與風險：** 一是合成與真實的落差（domain gap）：RCWA 沒涵蓋的材料或製程漂移，網路學不到。二是外插失準——遇到訓練分布外的新結構，預測可能自信卻錯。三是模型會 drift，需定期用實測再校正。這些都是編輯整理的通則，不代表任一特定產線的做法。

> 👷 對半導體工作者的意義：量測吞吐與回饋速度，往往是良率 ramp 的隱形瓶頸。ML-OCD 讓 inline 量測有機會從「抽樣」走向「近全檢」，但量測／良率／整合工程師要把「模型信心與不確定度」納入判讀，別把神經網路的輸出當成無條件真值。
