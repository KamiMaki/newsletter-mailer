## 🎯 今天的主軸｜信任的預設值翻面了：預設擋、預設短命、預設留記號

**共同變化**：過去平台的邏輯是「先給你方便，出事了你自己去關」；這週幾件事同時反過來：**GitHub** 宣布 12 月 2 日起，公開 repo 的 pull_request_target 事件預設被擋（原訂 11 月 2 日，已延後，並安排 11/9、11/16 兩次 16:00–18:00 UTC 的「停電演練」，其間被擋的 run 會直接失敗）；**GitHub Desktop** 開始對符合資格的帳號發「短命、自動刷新」的認證 token；**Anthropic** 在 11/3 的平台更新中，讓 Mythos 5、Opus 4.7、Sonnet 4.6 產生的文字預設帶上不可見浮水印。  ｜

🔗 [閱讀原文](https://github.blog/changelog/2026-11-02-pull_request_target-blocked-by-default-december-2) ｜ 來源：GitHub Changelog

🔗 [閱讀原文](https://github.blog/changelog/2026-11-02-github-desktop-adds-short-lived-authentication-tokens) ｜ 來源：GitHub Changelog

🔗 [閱讀原文](https://platform.claude.com/docs/en/release-notes/overview) ｜ 來源：Claude Platform Release Notes

**為什麼放在一起看**：三者看似不相干（CI 權限、登入憑證、AI 文字溯源），但邏輯相同：不再假設「呼叫者／輸出者／憑證持有者」值得信任，而是把防線寫進預設值。pull_request_target 之所以危險，是因為它在主 repo 的脈絡下跑、能讀 secrets，若又去跑 fork 傳來的不可信程式碼，就等於把鑰匙交給陌生人；短命 token 則是把「洩漏後能用多久」壓縮；浮水印則是讓「這段文字是誰產的」可以事後查證。

**過去 vs. 現在**：過去：安全設定在文件裡，靠使用者自己打開；token 一發好幾個月；AI 文字出了門就無從追溯。現在：預設就是封鎖／短命／帶記號，想要例外得明確申請（GitHub 是在 Actions event policy 中明確允許）。比喻：以前像大樓門禁「預設開門、要鎖自己鎖」，現在改成「預設鎖門、要進去刷卡登記」。回到技術：重點不是多一道功能，而是例外要被看見、被記錄。

**背後邏輯**：兩個推力。一是攻擊面：agent 與自動化流程越多，「可信輸入／不可信輸入」的界線越容易被踩破，平台只好用預設值替人擋。二是法規：Anthropic 說明已簽署歐盟 AI Act 第 50(2) 條的透明度實務守則，2026/8/2 起在歐盟新上線的模型要支援機器可讀標記，並在全球一併套用；檔案（PNG、JPEG）則附 C2PA 標準的簽章式 Content Credentials。（法規脈絡出自 Anthropic 支援頁；「為什麼 GitHub 同時調整」屬編輯推論，官方未說明兩者有關。）

🔗 [閱讀原文](https://support.claude.com/en/articles/16266773-how-claude-marks-ai-generated-content) ｜ 來源：Anthropic Support

**對你的工作**：半導體團隊的 EDA／驗證流程大量依賴 CI 與自動化腳本：若你的 repo 是公開的（例如開源 IP、RISC-V 核心、工具外掛），先到 Actions 的 Insights 查哪些 run 會被擋；內部私有 repo 與 Enterprise Server 不受此次影響。另外，盤點團隊手上還有哪些長效 token、AI 輔助產出的文件（規格、測試報告）是否需要留下來源標記。

**限制與待驗證**：(1) 浮水印不是鐵證：Anthropic 自己寫明，偵測到只代表 Claude 可能參與過，且 Claude 可能只是校稿或翻譯；沒偵測到也不代表不是 AI 寫的（短文、大幅改寫、舊模型、Sonnet 4.6 使用非預設取樣參數時可能沒有）。偵測能力目前僅對合格組織開放私人預覽。(2) GitHub Desktop 公告沒說 token 實際壽命，也是逐步推出。(3) 預設值只擋「忘了關」的人，擋不了刻意開例外的人。

**記住這句**：安全不再是你要記得去開的開關，而是你得說明為什麼要關的例外。

> 👤 延伸解讀（編輯分析）：這波變化的共同副作用是「例外管理」變成新的日常工作：誰申請了 pull_request_target 例外、哪個服務帳號持有長效憑證，都要有人定期清點。這是編輯推論，不是官方說法。

## 📖 今日概念｜鎖定檔（Lockfile）與可重現性

**一句定義**：鎖定檔把「依賴實際裝了哪個版本、雜湊值是多少」寫死成清單，讓任何人任何時間重新安裝都得到一模一樣的結果。

**生活化比喻**：像食譜只寫「麵粉」不夠，鎖定檔寫的是「某品牌、某批號的麵粉」。回到技術：apm.yml 寫範圍，apm.lock.yaml 記錄實際選中的版本。

**工作中的例子**：驗證團隊的 testbench 昨天跑得過、今天掛掉，往往是某個 Python 套件或 agent 技能被偷偷升級。有鎖定檔，就能確定是自己改了，還是依賴變了；Dependabot 則負責在你看得到的 PR 裡升級並重新產生鎖定檔。

**常見誤解**：「鎖定檔等於不更新」——錯，它是讓更新變成一次明確、可審查、可回退的動作；另一個誤解是鎖了就安全，鎖定的版本若本身有漏洞，仍然需要安全性更新。

**與今天主軸的關係**：預設值翻面的精神是「變化要被看見」；鎖定檔把依賴的變化變成可審查的差異，是同一件事的另一面。

## 🏭 半導體 AI 專區｜GPU 加速的計算微影與電漿模擬（物理代理模型）

**分類：** IC 製造

**內容屬性：** 今日新聞＋背景知識

**問題與流程位置**：製程開發要不斷試錯：改一個蝕刻條件或微影遮罩，要靠物理模擬預測結果，而高精度模擬動輒數小時到數天，工程師只能少試幾次。這發生在製程整合、設備與微影／蝕刻的模型與驗證環節。

**AI 如何介入**：今日新聞事實（NVIDIA 11/3 部落格，數字皆為合作廠商自述的「最高」值）：Siemens 將 cuLitho 整合進 Calibre 計算微影，關鍵工作負載最高加速 17 倍；Lam Research 展示以 PhysicsNeMo 在毫秒內預測電漿行為，對比完整模擬需數天；Applied Materials 的 ACE+ 形貌模擬最高快 35 倍、Ginestra 最高快 10 倍；Advantest 以代理自動選擇該用哪個 AI 模型，把回應從數小時縮到數分鐘。過去是「排隊等模擬」，現在是「先用代理模型快速篩選，再用完整模擬確認少數候選」。

**資料與產出**：輸入是既有物理模擬產生的資料、腔體與製程參數；產出是毫秒級的預測（電漿分布、形貌、微影驗證結果）供工程師決策。

**如何驗證**：編輯分析：代理模型只在訓練涵蓋的條件內可信，仍需以完整物理模擬或量測抽樣校準，並設定超出範圍時退回高精度模擬的規則。文章未公布精度、涵蓋範圍或量產導入規模。

**限制與風險**：倍數是「最高」且為廠商自述；各家未揭露驗證數據。背景知識：替身模型的外推風險是已知問題。不可把示範等同量產落地。
