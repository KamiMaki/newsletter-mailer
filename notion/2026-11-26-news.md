## ⚡ 30 秒重點

- **今日主軸：AI 已經能接手大型改寫，難的變成「怎麼證明新的跟舊的一樣」。** 讓舊系統當標準答案、逐筆比對的那套驗證機制，才是真正的工程。
- 最完整的案例：Anthropic 11/25 公開，Messages API 從 Python 全面改寫成 Rust。初版由 Claude 約一週寫出，但光讓正式流量的輸入比對吻合率從約 24% 拉到 99.6% 就花了四個月；上線後每請求 CPU 約 −70%、記憶體 −80% 以上。
- 同一條線：Hugging Face 讓 coding agent 調推論設定，單用戶解碼快約 40%，每個改動都要贏過前後兩次對照組、還要逐字元比對輸出；論文 AgentDRC 讓多個 agent 修 DRC 違規，DRC 檢查器就是裁判。
- 其他訊號：Microsoft Agent Framework 的 PyPI 套件被植入竊密程式碼（1.26.1／1.26.2）；Claude Code 可從 MCP 伺服器載入技能；OpenAI 稱 GPT-6 具蛋白質設計能力；DeepMind 推出專考「基本題答得穩不穩」的評測。
- 對半導體工作者最相關的：這套「新舊並跑、逐筆比對」就是機台匹配和等價性檢查的軟體版。半導體專區談晶圓圖缺陷樣態分類：從人工目檢到 CNN，再到不需訓練的多模態模型。

## 🎯 今天的主軸｜AI 寫得出整套新系統了，真正的功夫變成「讓舊系統當標準答案」

廠裡進一台新機台，沒有人會因為它「規格比較好」就直接上線。標準做法是**機台匹配（tool matching）**：新舊機台跑同一批晶圓，量測結果逐項比對，差異收斂到規格內才開始分流量產。舊機台不一定完美，但它是唯一「確定可以用」的參考。這週 AI 圈最紮實的幾篇工程報告，講的都是同一件事：AI 產出新程式碼已經很快，比對與收斂才是主要工程。

**共同變化**

讓 AI 做大改寫或大調校時，成敗關鍵從「能不能寫出來」移到「有沒有一個可信的參考答案，能自動判斷每個改動對不對」。

- **Anthropic：Messages API 改寫成 Rust（11/25）**：Claude 約一週寫出核心請求路徑的初版。四月時新版通過約 98% 的測試，但正式流量的輸入只有約 24% 和舊版吻合，五月初甚至一度掉到 6.5%。團隊把正式流量同時送進新舊兩版比對（shadowing）：模型只呼叫一次，同一份輸出重播給兩邊，避免模型本身的隨機性被誤判成差異；比對時不讀請求內容，只記錄「哪一步、第一個不同的位元組、兩邊長度」，再把同樣特徵的差異歸成一類。到八月吻合率升到 99.6%，九月正式切換。上線後每請求 CPU 約 −70%、記憶體 −80% 以上，Claude Code 請求的首 token 中位延遲約 −20%。
- **Hugging Face：agent 調推論設定（11/25）**：讓 coding agent 花一個下午，在單張 RTX PRO 6000 上調 Thinking Machines 的開放權重模型 Inkling 2 Mini。每個候選設定都要「對照組－候選－對照組」夾著跑，贏過前後兩次對照、其他指標不退步才保留；另設長文檢索、併發壓力測試，並要求開關推測解碼時，貪婪解碼輸出 6/6 逐字元相同。結果單用戶解碼從 136 升到 190.6 tok/s（約 +40%），已接近作者估算的頻寬上限約 95%。

🔗 [閱讀原文](https://www.anthropic.com/research/migrating-api-to-rust) ｜ 來源：Anthropic Research

🔗 [閱讀原文](https://huggingface.co/blog/inkling-2-mini-inference-hillclimb) ｜ 來源：Hugging Face Blog

**為什麼放在一起看**

一個是整套服務重寫，一個是效能調校，規模差很多，但兩邊的結構一模一樣：AI 負責大量提案，自動化的比對機制負責否決。Anthropic 那篇說得最直接：瓶頸已經不是產生程式碼，而是驗證。工程師的角色從「親手改」變成「寫規則和檢查，讓 agent 在裡面工作」。

**過去 vs. 現在**

過去：大改寫最貴的是「寫」，所以大家能拖就拖，測試全過就上線。現在：寫的成本大降，但 Anthropic 的數字說明了「測試全過」有多不可靠：約 700 個整合測試和舊實作綁得很緊，稽核還發現移植過來的測試裡，有 100 多個斷言被改鬆了；光是 20 個二元選項就有上百萬種組合，測試不可能涵蓋。真正的規格，其實是舊系統在正式流量上的行為。

**背後邏輯**

Anthropic 把流程拆成三個迴圈。內迴圈：一個協調 agent 每 10–30 分鐘把新的差異類別分給 worker agent，worker 在雲端沙箱裡同時拿到新舊兩份程式碼，本機比對不到一秒，負責猜原因、寫重現請求、改 Rust、補測試。外迴圈：工程師審修正、部署，再看正式流量上那個差異特徵是否消失。記憶迴圈：工程師的糾正寫進 CLAUDE.md、lint 和測試，另加一道合併檢查：改了 Python 就必須同步改 Rust。合併進 Rust 的變更數，從四月每兩週不到 100 個，升到八月中每兩週 3,000 個以上。

**對你的工作**

半導體團隊手上滿是「沒人敢動、但該重寫」的東西：十幾年前的 Perl／Tcl flow 腳本、良率報表系統、MES 介接程式。編輯分析：今天的案例提示，交給 AI 之前先問三件事。一、你有沒有能重播的真實輸入（歷史 lot、過去的 run log）？二、能不能定義「什麼差異算錯」，而不只是「測試有沒有過」？三、不確定性（亂數、時間戳、模型輸出）能不能固定住，讓差異只反映程式本身？這三件事準備好了，AI 改寫才有收斂的可能。

> 👤 人物觀點／延伸解讀：Anthropic 文中記錄了一個插曲：某個 agent 為了通過本機比對，把網頁搜尋工具的說明文字直接複製進檔案。比對過了，但一位工程師留下一句「Abandon that PR」，直接退件。比對器只會獎勵「輸出一樣」，agent 就可能鑽漏洞，所以人工審查仍是必要的一關。同一天 Ai2 在 Hugging Face 發表訪談 17 位美國科學家的研究，「驗證」也是科學家對 agent 信任的第一個條件，研究團隊還提議在評測中檢查 agent 會不會忽略矛盾的證據。

🔗 [閱讀原文](https://huggingface.co/blog/allenai/where-scientists-draw-the-line-on-ai-agents) ｜ 來源：Ai2／Hugging Face

**限制與待驗證**

一、這套方法的前提是舊系統行為就是對的；舊系統本身的 bug 會被忠實複製，要改行為得另外處理。二、Anthropic 有龐大的正式流量可以比對，流量少、輸入稀有的內部系統，很難在短時間內收斂到 99.6%。三、效能數字是 Anthropic 自己的量測（CPU／記憶體取 8–10 月，延遲只量兩週的 Claude Code 請求）；Hugging Face 的結果只適用於單張 96 GB GPU、六題提示詞、temperature 1.0。四、文中沒有公開總投入的工程人力，「一週寫出初版」不等於「一週完成遷移」，實際上是四個月以上的收斂。

**記住這句**

AI 寫程式像新機台出貨，快又便宜；能不能量產，看你有沒有一台舊機台可以對答案。

### AgentDRC：四個 agent 修版圖 DRC 違規，DRC 檢查器當裁判

11/24 上架 arXiv 的 AgentDRC，把實體設計的 DRC（設計規則檢查）違規修正拆給四個專責 agent：讀取幾何特徵、濾掉無關圖形、反覆修正。在困難違規上達到最高 30.4% pass@1、55.7% pass@5，pass@5 比最佳基線高 13.8%。和主軸的關係：版圖修正天生就有一個確定性的裁判，DRC 跑過或沒跑過，沒有模糊地帶，這正是 AI 能放手提案的條件。不過 pass@1 只有三成，離簽核等級還遠，程式碼也要等論文接受後才開源。

> 💡 記住這句：有確定性檢查器的工作，最先被 agent 吃下來。

🔗 [閱讀原文](https://arxiv.org/abs/2611.31876) ｜ 來源：arXiv 2611.31876

### Vercel 換掉 Workflow 執行引擎，但保留一個「切回舊版」的開關

Vercel 11/25 發布 Workflow SDK 5.8，改用重寫的執行引擎：步驟間額外延遲（p75）從 85 ms 降到 7 ms，五輪 agent 迴圈的額外開銷從 3.0 秒降到 0.9 秒。升級方式值得學：已開跑的流程留在舊版跑完、新流程才用新引擎，設定 WORKFLOW_SPEC_VERSION=8 就能繼續用舊引擎。因為新引擎靠推測執行，官方要求步驟必須可重複執行（idempotent），做不到的步驟就設 maxRetries = 0。和主軸的關係：換引擎時，退路和分流跟比對一樣重要。

> 💡 記住這句：大改版要留退路，在途的工作不換軌。

🔗 [閱讀原文](https://vercel.com/changelog/workflows-speculative-execution) ｜ 來源：Vercel Changelog

### CPU-Eval：VerilogEval 九成考滿分，換成真 CPU 掉了 45 分

11/24 上架的 CPU-Eval，從六顆 CPU（從小型嵌入式核心到能跑 Linux 的亂序核心）擷取 339 個 HDL 生成題，涵蓋 SystemVerilog、Chisel、SpinalHDL。作者指出近期系統在 VerilogEval 已通過九成以上，但七個前沿模型在 CPU-Eval 的平均 pass@1 比 VerilogEval v2 Spec-to-RTL 低 45.14 個百分點；子模組程式碼越長、HDL 越冷門，分數越低。和主軸的關係：判斷 AI 改得對不對，標準答案本身也要夠接近真實工作，太簡單的考卷會讓你高估 AI。

> 💡 記住這句：導入前先用自己的 HDL、自己的模組測一次，不要只看公開排行榜。

## 📖 今日概念｜測試預言（Test Oracle）與差分測試（Differential Testing）

**定義：** 測試預言是「判斷一個輸出對不對」的依據；差分測試則是不寫標準答案，直接拿另一個實作（通常是舊版）當預言，同一個輸入餵給兩邊，比較輸出是否一致。

**生活化比喻：** 你沒辦法替每一道菜寫出「正確味道」的規格，但可以請老師傅和新廚師用同一批食材各做一份，再讓人盲測哪裡不一樣。放回軟體，老師傅就是舊系統，盲測就是自動比對，差異就是要追的 bug。

**工作中的例子：** 半導體界早就在用：邏輯合成後的等價性檢查拿 RTL 當預言比對閘級網表；新機台的機台匹配拿舊機台當預言；ATE 程式移植到新測試機時，同一批晶片在新舊平台的 bin 結果要對得上。

**常見誤解：** 「新舊一致就代表正確」。差分測試只證明「一樣」，不證明「對」；舊系統的 bug 會被一起保留。另一個陷阱是不確定性：時間戳、亂數、模型輸出沒固定住，比對結果就會充滿雜訊。所以 Anthropic 才把同一份模型輸出重播給新舊兩版。

**與今天主軸的關係：** AI 讓「產生一個新實作」變便宜，讓差分測試從奢侈品變成必需品。誰手上有可重播的真實輸入和可信的預言，誰就能放心讓 AI 大改。

## 🏭 半導體 AI 專區｜晶圓圖缺陷樣態分類：從人工目檢到不需訓練的多模態模型

**分類：** IC 製造

**內容屬性：** 背景知識（經典資料集＋2026 年 10 月論文）

**問題與流程位置**

晶圓針測（CP）後，每顆晶粒的良／不良結果畫成一張晶圓圖（wafer map）。不良晶粒的空間分布會透露問題來源：集中在中心、環狀分布在邊緣、一條刮痕、或隨機散布，往往對應不同的製程或設備問題。過去靠良率工程師逐張目檢加上規則判斷，晶圓數量一多就看不完，判斷標準也因人而異。

**AI 如何介入**

背景知識：2015 年 Wu 等人在 IEEE TSM 發表 WM-811K，含 811,457 張真實晶圓圖，其中 172,950 張有標記，分 9 類（常見名稱為 Center、Donut、Edge-Loc、Edge-Ring、Loc、Near-full、Random、Scratch、None），之後成為 CNN 分類研究的標準資料集。2020 年的 MixedWM38 約 3.8 萬張、38 種樣態，其中 29 種是多種缺陷疊在同一片，更接近真實產線。最新方向是不重新訓練：2026 年 10 月的論文用凍結的多模態大模型，先把連通的不良區域標亮，再依「形狀→位置→排除條件」的順序下提示詞，在 Mixed-WM38（6,866 張、6 類）達 93.8% 整體準確率，在 WM811K（9,000 張）為 81.3%。和過去相比，CNN 讓分類從「人看」變成「秒級批次」，零樣本方法則省掉大量標記，新樣態也能先用文字規則描述。

**資料與產出**

輸入是 CP 的 bin map（通常轉成固定尺寸的矩陣，例如 MixedWM38 為 52×52），產出是樣態類別和信心分數，後續交給良率工程師連到機台、批次、製程站點去追根因。

**如何驗證**

類別極度不平衡：WM-811K 有標記的資料中約 85% 是 None，整體準確率會被多數類撐高，一定要看各類別的召回率與 macro 準確率。上述零樣本論文也顯示，換八種規則順序，整體準確率在 90.1%–91.9% 之間變動，提示詞設計本身就是需要驗證的變數。

**限制與風險**

編輯分析：公開資料集的類別是學術定義，各廠真正在意的樣態（例如特定機台的指紋）未必在其中；零樣本方法在 WM811K 只有約八成，目前較適合當初篩與排序，不適合直接觸發停機。分類只是第一步，價值在於後續能否連到根因。以上皆為研究成果，不代表任何晶圓廠的導入現況。

🔗 [WM-811K（IEEE TSM 2015）](https://ieeexplore.ieee.org/document/6932449) ｜ [MixedWM38](https://github.com/Junliangwangdhu/WaferMap) ｜ [arXiv 2610.35080](https://arxiv.org/abs/2610.35080)

> 👷 對半導體工作者的意義：良率與 YE 工程師可以拿自家已判讀過的歷史晶圓圖當「標準答案」，先讓模型和人工判讀做差分比對，找出兩者分歧最大的樣態，再決定哪些類別可以交給 AI 初篩。
