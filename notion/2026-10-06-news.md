## 🎯 今天的主軸｜agent 的競賽從「更聰明」轉到「跑得完、接得回、花得起」

**共同變化：** 10 月 5 日這天，三家做 agent 工具的公司（Cohere、Vercel、LangChain）各自出了更新。乍看互不相關，但攤開版本說明，它們補的是同一類問題：一個會跑好幾步、花好幾分鐘、要動用外部工具的 agent，中途斷了怎麼無損接回、花了多少錢看不看得到、能不能跑在自己機房裡。沒有一個是「模型更聰明了」。agent 的競爭重心，正從「能力」悄悄移到「交付」。

**為什麼放在一起看：**

① **Cohere North 2：把「治理」當產品賣。** North 2 幾乎不談模型多強，通篇在講可自架（on-prem／VPC／混合）、模型可換（model-agnostic）、成本看得住——新的 North Admin 能做細緻權限、用 flow control 盯 token 花費、設定用量分級。它拿 SOC 2 Type 2、ISO 27001、ISO 42001 三張認證當門票，agent 編排（Skills／Memory／Automations／接 Slack、SharePoint、Jira）反而是配角。

② **Vercel AI SDK 7.0.128：給 agent 補上「可持久化」。** 這版最大的改動，是新增非串流、可持久化的 `WorkflowAgent.generate()`（共用工具迴圈、預設跑 20 步、輸出帶型別），以及一句關鍵修正——「串流中斷恢復時，保留工具的授權狀態」。白話說：agent 跑到一半你關掉或斷線，再開回來時它記得「哪些工具你已經按過同意」，不用從頭再問。

③ **LangGraph 1.2.13：修的是 checkpoint 的老毛病。** 這版修掉兩個 checkpoint（存檔點）相關的 bug：從一個「執行緒已經跑過去的」存檔點分叉重放時會出錯、以及狀態更新計數器沒被正確保留。聽起來很細，但這正是「斷點續跑」能不能信得過的地基。

**過去 vs. 現在：** 過去一年大家秀的是 demo：丟個任務，agent 噠噠噠跑完。但 demo 和生產隔著一條河——demo 跑一次就好，生產要跑一千次、每次都可能在第 7 步因網路、逾時或人去睡覺而中斷。過去這些中斷幾乎等於「整個任務作廢、重跑」；現在這週的更新全在把「中斷」從災難降級成「存檔、接回、繼續」。像遊戲從「一命通關」進化到「隨時存檔」——不是關卡變簡單，是你終於輸得起了。

**背後邏輯：** 模型夠不夠聰明，這一年已經不太是 agent 落地的卡點——卡點是可靠性與可控性。一個 agent 要進企業真實流程，公司問的三題永遠是：它斷了會怎樣（韌性）、花了我多少（成本）、資料跑去哪（治理）。這週三家回答的正是這三題。這也解釋了為什麼差異化越來越不在模型本身——模型大家都能接，難做又值錢的是把它穩穩塞進生產環境的那層工程。

> 👤 編輯分析：這三則本身有大有小——North 2 是完整產品發表，Vercel 和 LangGraph 嚴格講是版本更新裡的功能與修補。把它們串成「同一條線」是編輯的觀察，不是哪家喊出的口號。但當三家做法完全不同的公司在同一天各自往「可恢復、可控、可自架」補東西，反映的是整個 agent 工程社群的共同焦慮：demo 做完了，接下來要過生產這一關。

**對你的工作：** 若你在評估要不要把 agent 放進團隊流程，這週的訊號是：選型時別只比模型分數，要比「斷點續跑、成本上限、部署位置」這些工程能力。尤其半導體這種跑長流程（一次模擬／驗證可能幾小時）、又在意資料留在廠內的場景，一個「斷了要從頭來」的 agent 根本不能用。

**限制與待驗證：** 別讀成「agent 韌性已解決」。Vercel、LangGraph 的更新都還是框架層零件，要真正「斷哪都接得回」，你的每步工具呼叫還得自己設計成可重放而不重複副作用（見今日概念），框架不會自動幫你擦屁股。North 2 的成本與自架宣稱也要以實際部署為準，官方 token/node 數字是搭配 NVIDIA 硬體的情境值，非普遍保證。

**記住這句：** agent 這一年要過的不是「更聰明」，是「跑得完、接得回、花得起、放得心」——這週的更新全在補這格。

## 📖 今日概念｜持久化執行（Durable Execution）

**一句定義：** 持久化執行是指一段長時間、多步驟的程式（例如一個 agent 工作流），把每一步的進度與狀態存下來，讓它在當機、逾時或重啟後能從斷掉的地方接著跑，而不是從頭來過。

**生活化比喻：** 像打一款會自動存檔的遊戲：打到第三關突然停電，重開後不是回到片頭，而是回到第三關的存檔點。回到技術：那個「存檔點」就是 checkpoint，「重開後照紀錄追回進度」就是 replay（重放）——持久化執行就是把這套存檔／重放機制，套在一段隨時可能中斷的程式上。

**工作中的例子：** 一個採購 agent 要「查供應商 → 下單 → 寄確認信」三步，跑到第二步下完單後伺服器重啟。有持久化執行，它重開後知道「單已下，別再下一次」，直接跳到寄信；沒有的話，最糟是重跑整段、重複下單又重複付款。

**常見誤解：** 「有 checkpoint 就安全了」——不完全對。能接回的前提是每一步都要可重放而不產生重複副作用，也就是要有「冪等性」（同一步做一次和做兩次結果一樣）。框架幫你存檔，但「下單別下第二次」這種保護多半得你自己在每步設計進去。

**與今天主軸的關係：** 今天 Vercel 的「可持久化 WorkflowAgent」「恢復時保留工具授權」，和 LangGraph 修的 checkpoint 分叉／重放問題，講的全是同一件事的不同零件。持久化執行，就是把 demo agent 變成生產 agent 的那道門檻。

## 🏭 半導體 AI 專區｜用機器學習決定「這一刻該停蝕刻」

**分類：** IC 製造
**內容屬性：** 背景知識

**問題與流程位置：** 電漿蝕刻（plasma etch）是把晶圓上不要的材料一層層「啃」掉的製程。最關鍵的一刻是「何時收手」——這叫終點偵測（Endpoint Detection, EPD）：停太早該蝕的沒蝕乾淨，停太晚會傷到下層、尺寸跑掉。傳統做法是盯著電漿發出的光（光學發射光譜，OES）——某波長強度在材料被蝕穿那瞬間會轉折，就以此判斷。它位在製程進行中的即時控制這一環。

**AI 如何介入：** 問題出在開口面積很小的圖案（例如僅 1% 開口率）：被蝕穿的訊號太微弱、淹沒在雜訊裡，盯單一波長根本看不出轉折。過去工程師靠經驗設固定門檻、單一波長，常常失準。AI 的做法是改看「整張光譜」：把 OES 幾百個波長一起餵進模型——用 CNN 這類分類器學會辨認「蝕穿前 vs. 蝕穿後」的整體模式，或用非監督式的 PCA＋分群，不靠人工標註就把終點那一刻分出來。和過去最大的差別：從「盯一條線的轉折」升級成「讀整片頻譜的指紋」，微弱訊號也救得回來。

**資料與產出：** 輸入是蝕刻過程中逐秒採集的多波長 OES 時間序列；輸出是「現在是否到達終點」的即時判斷（分類器）或「狀態已轉變」的訊號（分群）。訓練資料多半是過去跑過、已知終點時刻的批次。

**如何驗證：** 關鍵是別只看平均準確率，要看在最難的低開口率圖案上，模型抓終點的時間誤差有多小，以及換圖案、換機台還準不準（可遷移性）。實務上會先用事後的斷面量測（SEM）回頭對答案，確認模型判的終點和真實蝕穿時刻對得上，再逐步放進產線當輔助。

**限制與風險：** 這仍以學界與設備商的研究為主，不代表已全面量產落地；模型最怕「只認得訓練過的製程」，換配方或換腔體條件就可能失準。而且蝕刻不可逆——判錯一刻就報廢一片，所以通常當輔助訊號，與既有物理模型並行，而非直接放手讓它一個人決定停手。（以上為背景知識與公開研究，非 48 小時內新聞，也非特定廠商量產數字。）

> 👷 對半導體工作者的意義：對製程整合與設備工程師，這和今天主軸是同一個母題——「在一段不可逆的長流程裡，靠即時狀態判斷『該不該停、停在哪一刻』」。值得留意的下一步，是把多波長 OES 的 ML 終點模型當輔助訊號接進低開口率的難蝕製程，先驗證時間誤差與跨機台穩定度，再談放進產線。

## 🪞 反思時間

- 如果你要把一個 agent 放進真實流程，你會怎麼回答老闆的三連問——「它斷了會怎樣、花了我多少、資料跑去哪」？這三題裡，你現在最答不出來的是哪一個？
- 你團隊現有的自動化流程裡，有哪一段是「中途斷掉就得整個重來」的？把它改成「可存檔、可接回」要付出什麼代價，又能省下什麼？
- 當模型能力逐漸商品化、差異化移到「交付工程」這層，你所在的角色（晶片、EDA、製造）裡，最難被取代的「把東西穩穩做出來」的工程能力是什麼？

**🎒 今日帶走：** agent 的下一哩路不是更聰明，是夠可靠——能存檔、能接回、花費看得住、部署在自己地盤。
