## 🎯 今天的主軸｜AI 代理正在領到「員工證」——從你呼叫的工具，變成會自己一直跑的常駐同事

先講一個畫面。以前你用 AI，比較像叫一位**工讀生**：你交代一句、它做一次、你盯著看完，事情結束它就走。本週 9/24～9/25 有一批看似不相關的發布，其實共同把這個關係改寫了——AI 代理開始領到「員工證」：有自己的名字與權限、被交付一段**持續的任務**、而且不需要你每次按一下才動。工讀生變成了正職同事。

**共同變化：** 三則發布指向同一件事。**Amazon** 9/24 升級 Seller Assistant，讓代理工作流「在背景持續執行」，賣家**不必登入 Seller Central**也能 24 小時自動盯庫存、調價格、處理例行任務。**微軟** 9/25 改版 Copilot，端出名為 **Autopilot** 的代理，官方形容它是「數位同事」，特點就是**會自己接著做，而不是等你下一個指令**。新創 **Ando** 更直接——做了一個給人和 agent 共用的團隊通訊軟體（對標 Slack），agent 在裡面是**有持久身分與權限的「正式成員」**，拿了 2,000 萬美元種子輪。

**為什麼放在一起看：** 三家公司、三個場景，卻都在把 agent 的身份從「被呼叫的功能」推向「常駐的執行者」。差別藏在三個小地方：**不必登入**（Amazon）＝沒有人坐在螢幕前按執行；**自己接著做**（微軟）＝任務是連續的，不是一問一答；**是團隊成員**（Ando）＝它有名字、有權限、會被別人 @。當「常駐、連續、有身分」三件事同時成立，AI 就從工具變成了組織裡的一個角色。

**過去 vs. 現在：** 過去你開著視窗打一句話，AI 給建議、你確認、你送出——人是引擎，AI 是副駕。現在你設好規則與上限，agent 在你睡覺時自己巡、自己改、把每一步記進稽核紀錄——AI 是引擎，人退到監工與稽核。這就是為什麼 Amazon 特別強調它帶「完整稽核軌跡」與「賣家自訂的護欄」：沒有人盯著的時候，稽核與護欄就是唯一的煞車。

**背後邏輯：** 為什麼是現在？因為模型「一次做對一長串步驟」的能力終於夠用了。Amazon 說 Seller Assistant 一次可編排上百個步驟、動用上百項賣家指標。能力到位後，產品公司要賣的就不再是「更聰明的答案」，而是**一段可以放手的持續勞動力**——按「做完的事」收費比按「聊幾句」收費值錢得多。這也是為什麼大家搶著把 agent 塞進你已經在用的地方（賣家後台、團隊聊天、Office），而不是再開一個新視窗：常駐同事要坐在辦公室裡，不是待在門外。

**對你的工作：** 如果你管團隊或流程，這週的訊號是：你的下一個「新人」可能是個 agent，而報到流程完全不一樣。人類新人你給帳號、給權限、給主管；agent 新人你要給的是**範圍受限的憑證、明確的護欄、和一條查得到的稽核軌跡**。而且它不會累、不會下班，所以「誰在監工、出事誰負責」必須先想清楚。

**限制與待驗證：** 別急著全信。第一，這些多半是剛發布或 Beta，「會自己做」和「做得對」是兩回事，長工作流一步錯就可能連錯。第二，責任歸屬還是灰色地帶——agent 半夜把價格調錯，帳算誰的？第三，稽核不等於控制：事後查得到，不代表當下擋得住。這也是為什麼「管理 agent」本週立刻變成生意。

> 👤 編輯分析：把這週和上週對照很有意思——前幾天大家談 agent「更會做研究、更會編排」，這週談的是 agent「拿到了辦公室的座位」。能力面已經卷得差不多，戰線正在移到組織面與治理面：不是「AI 能不能做」，而是「你敢不敢讓它自己做、要怎麼給權限、出事怎麼查」。（此段為編輯觀察，非官方說法。）

**記住這句：** AI 代理正在從「你按一下的工具」變成「會自己一直跑的常駐同事」；當沒有人盯著時，權限邊界與稽核軌跡才是真正的產品。

## 📖 今日概念｜委派授權與範圍受限的代理憑證

**一句定義：** 「委派授權（scoped delegation）」是指你不把完整權限交給 AI 代理，而是發給它一張用途受限、金額受限、時效受限、可隨時收回的「臨時通行證」，讓它只能在你劃定的範圍內替你動作。

**生活化比喻：** 像你請助理去採買，你不會把整張信用卡＋密碼給他，而是給一張**預付卡**，寫明「只能在這家店、上限 3,000 元、今天有效」，刷完就作廢、弄丟也只損失卡裡的額度。技術上就是這張預付卡：一枚綁死金額、對象、期限的**一次性憑證（scoped token）**，而不是你的本尊帳號。

**工作中的例子：** 這正是本週 Google **Credentials API** 在做的事——讓代理「安全地」拿憑證動用外部服務，而不是把主帳號密碼塞給它。更完整的產業標準也已成形：Google 的 **AP2（Agent Payments Protocol，已捐給 FIDO 聯盟）**用兩張「簽章授權書（mandate）」把「你想買什麼、條件是什麼」和「用哪張卡、多少錢」分開簽；OpenAI 與 Stripe 的 **ACP** 則用一枚「共享付款 token」代表「只准向這家商店收這個金額」的一次性授權。（AP2／ACP 為既有官方標準文件，非今日新聞，列此僅供延伸理解。）

**常見誤解：** 誤解一「給 agent 我的 API key 就好」——那等於把整串鑰匙交出去，一旦外洩全盤皆輸；委派授權的重點是最小權限＋可收回。誤解二「有稽核紀錄就安全」——稽核是事後查得到，範圍受限的憑證才是事前就擋住越權，兩者是不同層的防線。

**與今天主軸的關係：** 主軸說 agent 變成「會自己動的常駐同事」，它要能自己動就得握有權限；而你敢放手的前提，就是這把權限是範圍受限、可收回、留痕的。委派授權，就是讓「放手」和「可控」同時成立的那張安全網。

## 🏭 半導體 AI 專區｜用深度學習做晶圓缺陷影像的自動分類（ADC）

**分類：** IC 製造
**內容屬性：** 背景知識

**問題與流程位置：** 晶圓在光刻、蝕刻、CMP、沉積等關鍵步驟後，會先用光學檢測機高速掃出「哪裡疑似有缺陷」，再把座標交給電子束／SEM 複檢機拍高解析照片。ADC（Automatic Defect Classification）要把這些缺陷照片一張張分類（顆粒、橋接、斷線、空洞、刮傷、圖案缺陷……），排出缺陷 Pareto 給良率工程師追根因。痛點很直接：產線一天可產出數以百萬計的缺陷影像，靠人工看不完，且判讀不一致，容易漏殺或過殺。（註：這與「晶圓圖缺陷『樣態』分類」不同——後者看整片晶圓上不良晶粒的空間分布、用電測資料；本篇談的是單顆缺陷的顯微影像。）

**AI 如何介入（與過去的差異）：** 過去靠規則式＋人工特徵（用大小、形狀、灰階門檻寫規則），每層要重調、對細微缺陷力不從心，仍需大量人工複檢。改用 CNN／深度學習後，模型直接從標註影像學特徵，一次輸出缺陷類別＋信心分數，吞吐量與一致性大幅提升。多家已落地：Applied Materials 的 ExtractAI 把光學檢測與電子束複檢即時串起來，訓練系統把「真的殺良率的缺陷」從一堆「雜訊型缺陷（nuisance）」挑出來；KLA、Hitachi High-Tech 的複檢 SEM 也內建 ML 版 ADC。核心差異從「人寫規則、人判讀」變成「機器學樣本、人審可疑案」。

**資料與產出：** 輸入為 SEM 複檢影像（高解析但雜訊多）、光學檢測影像、缺陷座標／晶圓圖，KLA 方案還帶入 CAD 設計資訊；輸出為缺陷類別＋信心、缺陷 Pareto、以及雜訊過濾。Applied 宣稱 ExtractAI 只需複檢約 0.001% 的樣本就能刻畫全部潛在缺陷、把上百萬個可疑點收斂到約一千個需處理（此為廠商聲稱值）。難點在資料：專家標註昂貴、類別極度不平衡（最致命的缺陷樣本反而最少）、影像需先去噪。

**如何驗證：** 業界用準確率、純度（purity）、分類率，並要求極低的漏檢率（escape rate）——把真缺陷誤判成雜訊是最貴的錯。做法是拿模型結果對人工判讀的混淆矩陣、保留未見缺陷做 holdout、並讓工程師專門審查低信心案例（人在環內把關）。

**限制與風險：** 一，遇到沒見過的新缺陷可能誤分或漏判（有研究加 k-NN 讓新型缺陷被標為「未知」而非硬塞舊類）。二，模型綁層綁製程，換層、換機、製程漂移就要重訓。三，雜訊 vs 真缺陷的界線本就難分。四，過度信任會讓漏檢流到下游——低漏檢率與人工抽審不能省。

> 👷 對半導體工作者的意義：這波「AI 自己動」的浪潮，對缺陷/良率/檢測工程師其實是熟悉的老問題新版本——關鍵永遠是「漏檢率」和「可疑就交回人審」那條回路。值得動手的下一步：把你手上 ADC 或檢測模型的漏檢率、以及低信心案例的人工回審比例攤開來看，這兩個數字才是「敢不敢放手」的真正指標。

## 🪞 反思時間

- 如果明天你的團隊要「雇用」第一個會自己一直跑的 agent，你會先劃定哪三條它絕對不能跨越的界線？這三條要靠「事前的權限」還是「事後的稽核」來守？
- Amazon 讓賣家「不登入也能運作」很吸引人，但也拿掉了那個「有人在當下按煞車」的時刻。以你的工作為例，哪些決定值得用便利換掉即時人工把關，哪些絕對不行？分界線畫在哪？
- 半導體的 ADC 幾十年來都用「低漏檢率＋人審可疑案」讓自動判讀可信。如果把同一套紀律搬到辦公室的 agent 上，你的流程裡「可疑就交回給人」的那條回路目前存在嗎？還是根本沒有？

**🎒 今日帶走：** AI 代理正在領員工證、變成會自己跑的常駐同事；決定它能不能放心上工的，不是它多聰明，而是你有沒有給它「範圍受限、可收回、查得到」的權限與稽核回路。
