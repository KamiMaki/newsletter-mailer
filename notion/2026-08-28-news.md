## 🎯 今天的主軸｜成本戰換武器：把巨模型做到「極稀疏」，每次只點亮約 5% 參數

先講一個生活比喻：以前想省油錢，做法是換一台小車（把模型做小）；但小車跑不快、載不多。今天中國兩間實驗室給的答案完全相反——造一台十二缸的大引擎，但每次只點火其中一缸。車體（總參數）依然巨大、能力依然頂尖，油錢（每次推論的算力）卻低到誇張。這台「大引擎、少點火」的技術，就是稀疏混合專家（Sparse MoE），而 8 月 26 日這一天，它同時走出兩座實驗室。

**共同變化：** 阿里 Qwen 團隊開源 Qwen3.8-Flash-Next：總參數 125B，但每個 token 只活躍 6B（不到 5%），外掛一張 51B 的 N-gram 記憶表與 4B 多 token 預測層，原生讀圖、262K 上下文。官方說它是「Qwen4 架構」的開放權重預覽，訓練成本只有 Qwen3.7-Plus 的九分之一，量產 API 定價 0.16 美元／百萬輸入、0.47 美元／百萬輸出。幾乎同一時間，智譜 Z.ai 揭曉 GLM-5.3-Flash——就是過去一週在 OpenRouter 上被匿名測試、代號「Ox Alpha」的那顆模型：320B 總參數、18B 活躍（320B-A18B），GLM-5 系列首顆原生多模態，MIT 授權、當天把權重丟上 Hugging Face，定價 0.15／0.50 美元（首發促銷再對折），還宣稱完全跑在中國自製 AI 晶片上。

**為什麼放在一起看：** 兩顆模型出自不同公司、不同架構，卻在同一天指向同一件事：前沿級能力正在跟「每次要花多少算力」脫鉤。Qwen 用「四層裡三層用 Gated DeltaNet 壓縮歷史、一層用稀疏注意力精準檢索」的混合設計；GLM 則號稱是首顆採「稀疏＋線性混合注意力」的開源前沿模型，把注意力運算砍到原本的 1/3、KV cache 縮到 1/4.4。手法不同，目標一致——在總參數繼續變大的同時，把「每個 token 的成本」壓垮。這不是單一產品新聞，而是一條產業主線正在成形。

**過去 vs. 現在：** 過去要省成本，你得在「聰明但貴的大模型」和「便宜但笨的小模型」之間二選一。現在的稀疏路線把這道選擇題拆開：模型可以同時很大（知識容量高）又很便宜（每次只算一小塊）。對照一年前，同樣的輸出量在頂級閉源模型上要花二、三十美元，如今這批稀疏開源模型只要幾毛錢，差距是一到兩個數量級。

**背後邏輯：** 稀疏化的代價不是消失，而是從「算力」搬到「記憶體」。125B、320B 的權重全都得放進記憶體待命，只是每次挑一小撮出來算。所以這條路線省的是 FLOPs 與電費，吃的是記憶體容量與頻寬——Qwen 甚至把那張 51B 的 N-gram 記憶表設計成「可非同步卸載到主機記憶體」，就是在跟記憶體牆討價還價。這也是為什麼它們同時強調「開放權重」：把便宜又能本地部署的權重丟出來，等於把定價權從閉源大廠手上搶一塊過來。

**對你的工作：** 如果你在團隊裡負責選模型或估算 AI 成本：「便宜到可以隨便跑」正在變成前沿的常態，這讓大量跑 agent、批次跑驗證、把 AI 塞進 CI 迴圈變得划算。但別只看每百萬 token 單價——稀疏大模型的部署門檻在記憶體：320B 權重要落地，你得算清楚 GPU 記憶體、量化方案與吞吐，單價便宜不代表自架便宜。對做工具鏈、做內部平台的人，這批 MIT／開放權重模型也讓「把前沿模型關進自家機房、資料不出門」第一次真的可行。

**限制與待驗證：** 三個保留：其一，官方跑分（GPQA Diamond 91.7、LiveCodeBench v6 91.9）亮眼，但 benchmark 分數 ≠ 你的真實任務可靠度，尤其 agent 長流程；其二，Qwen3.8-Flash-Next 自稱「實驗性預覽」，是 Qwen4 架構的搶跑版，穩定度與長期支援還要看；其三，「跑在中國自製晶片」是廠商說法，外部難以獨立驗證，屬編輯提醒而非既成事實。便宜、開放、能力強能不能三者兼得，得等社群大規模實測。

> 👤 延伸解讀（編輯分析／趨勢背景）：這股「稀疏 MoE 把價格打到骨折」的壓力不是今天才有——DeepSeek 早就靠 MoE 把同樣輸出壓到 Opus 級別的 1%，OpenAI 也在 8/21 宣布 GPT-5.6 Sol 三個月降價逾 20%、Google 連推三顆 Gemini「Flash」主打效率。今天 Qwen 與 GLM 的意義在於，它們把「稀疏 + 開放權重 + 前沿級」三件事一次湊齊。（此段為趨勢背景與編輯分析，非 48 小時內新聞。）

**記住這句：** 前沿模型變便宜的方式，已經從「做小」變成「做大但極稀疏」——省下的算力搬進了記憶體，而開放權重把定價權也一起搬走了。

## 📖 今日概念｜稀疏混合專家（Sparse MoE）

**一句定義：** 把一個大模型切成很多「專家」子網路，每個 token 只交給其中一小撮專家處理——所以模型「總參數」很大，但「每次真正動用的參數（活躍參數）」很小。

**生活化比喻：** 想像一間有 100 位專科醫生的大醫院。你掛號時，櫃檯（路由器）只會把你導去 2、3 位相關科別的醫生，而不是讓 100 位一起會診。醫院很大（總參數多、知識廣），但你這一次的看診成本，只等於那幾位醫生的時間（活躍參數少）。稀疏 MoE 就是這個櫃檯分流的機制。

**工作中的例子：** GLM-5.3-Flash 是 320B-A18B——320B 是整間醫院的醫生總數，18B 是你這次實際叫到的那幾位。Qwen3.8-Flash-Next 更極端，125B 總參數只點亮 6B。這就是它們能把每百萬 token 壓到一毛五的關鍵。

**常見誤解：** 「參數越多一定越慢越貴」。對稀疏 MoE 不成立——貴的是記憶體（所有醫生都得在院待命，權重要全部載入），慢與貴的「每 token 算力」反而因為只叫少數人而下降。所以 MoE 模型常是「記憶體吃很兇、但推論很快很便宜」。

**與今天主軸的關係：** 今天的價格崩跌，正是靠把活躍參數比例壓到 5% 上下換來的。理解「總參數 vs. 活躍參數」這組區別，你才看得懂為什麼一顆「更大」的模型可以「更便宜」，以及為什麼它的部署瓶頸會落在記憶體而不是算力。

## 🏭 半導體 AI 專區｜計算微影與逆微影（ILT）的 AI 加速

**分類：** IC 製造

**內容屬性：** 背景知識（含編輯分析），非 48 小時內新聞

**問題與流程位置：** 先進製程要在晶圓上印出比光波長還小的圖形，光一定會繞射、失真，畫在光罩上的圖案跟真正印出來的長得不一樣。所以在「設計定案 → 做光罩 → 曝光」之間，必須做光學鄰近修正（OPC）：把光罩圖形刻意畫歪，好讓印出來剛好對。逆微影（ILT）更進一步，直接反推「要印成這樣，光罩該長怎樣」，效果最好，但運算量大到過去難以全晶片量產使用。這一關卡在光罩製作前，是製造流程裡出了名的算力黑洞。

**AI 如何介入（與過去流程比較）：** 過去 OPC／ILT 靠 CPU 農場、逐點物理疊代，跑一個全晶片動輒數天。現在兩層加速疊上去：先是 GPU 加速的計算微影（如 NVIDIA cuLitho）把整條流程搬上加速運算；再用生成式 AI 直接「猜」出一張接近最佳的逆光罩，再交給嚴謹的物理方法收尾——官方數據是在 cuLitho 之上讓 OPC 再快約 2 倍。近期研究更把生成式強化學習用來推進 ILT 的極限。差別在於：AI 不是取代物理模擬，而是把「一張好光罩大概長怎樣」先秒出來，省掉大量疊代，讓 cycle time 從天級往小時級壓。

**資料與產出：** 輸入是設計版圖、微影/蝕刻模型與空間像模擬；產出是修正後的光罩圖形與 OPC/ILT 配方。對量產而言，這些產出最終要能餵進光罩廠與曝光機（含 ASML High-NA EUV 這一代對隨機效應更敏感的製程）。

**如何驗證：** AI 出的光罩不能直接信，要過三關：物理嚴謹的微影模擬、邊緣放置誤差（EPE）與製程窗（process window）檢查、以及對隨機缺陷（stochastic）的容忍度評估，最後回到晶圓上以 SEM 量測實印結果。AI 負責「快」，物理與量測負責「對」。

**限制與風險：** 生成模型的泛化是關鍵風險：換一層、換一個節點，模型不見得還準；隨機效應與極端圖形仍需物理方法兜底；整條流程並非「無人自動」，而是「AI 加速 + 工程師與物理守門」。以上工作流位置與加速倍數引自 NVIDIA、學術綜述與論文，屬背景知識與編輯分析，非 48 小時內新聞，也未涉及任何公司內部良率或機密數字。

> 👷 對半導體工作者的意義：最受影響的是光罩／OPC／DTCO 與微影工程師——計算微影是少數能同時壓 cycle time、又直接牽動良率爬坡速度的環節。值得動手的下一步：了解你們 PDK 裡 ILT／OPC 是否已上 GPU 加速，以及生成式方法在哪些非關鍵層可以先試點。（來源：NVIDIA cuLitho、Nature AI-based ILT 綜述、arXiv 2602.19027）
